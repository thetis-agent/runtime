# Thetis

A multi-user AI agent harness with a small trusted kernel, isolated environments,
and versioned packages.

## Install

On Linux with systemd 252+, cgroup v2 and working user namespaces:

```sh
curl -fsSL https://github.com/thetis-agent/runtime/releases/latest/download/install.sh -o install.sh
sudo sh install.sh
```

The installer uses `/opt/thetis`, `/var/lib/thetis` and `thetis.service`.
It downloads and verifies Node and the signed application, creates your
administrator account, asks for an OpenRouter model and API key, and starts
Thetis. API keys are encrypted; passwords are stored only as salted hashes.
Use `--prefix` and `--state` to choose your own deployment paths.

Talk to it immediately from the host:

```sh
sudo /opt/thetis/bin/thetis chat --message "Hello"
sudo /opt/thetis/bin/thetis status
```

For browser access, route your HTTPS endpoint to the login and person-scoped web
sockets printed by `status`. The trusted kernel uses a separate origin.
The [installation guide](docs/install.md) covers prerequisites, proxy routing,
other providers, explicit offline demo mode, updates, backups and removal.

## Develop

Clone the two repositories side by side. Use Node **24.18.0**, matching the
verified execution artifacts; `.nvmrc` records the version.

```sh
git clone https://github.com/thetis-agent/runtime.git
git clone https://github.com/thetis-agent/packages.git
cd runtime
nvm install
nvm use
npm ci --ignore-scripts
npm run build
npm run check
npm test
```

If you do not use nvm, install the exact Node version with your preferred
version manager. The package checkout defaults to `../packages`; set
`THETIS_PACKAGES` to use another location. Neither checkout has to be under
`/opt`, and development paths are never installation defaults.

The [platform requirements](docs/platform-dependencies.md) describe bubblewrap,
network isolation and cgroup delegation. Checks and tests always run in the
mandatory sandbox. Test files execute serially inside a bounded delegated user
scope; they need no real API keys, models or external network.

Rebuild after editing TypeScript. `check` verifies committed schemas, types,
installer freshness, strict TypeScript, lint and execution-artifact freshness.
Generate contract types only when their schemas change.

```sh
# Focused tests
node --import ./lib/artifacts/source.mjs scripts/test.ts lib/registry lib/profile

# The complete suite with coverage
node --import ./lib/artifacts/source.mjs scripts/test.ts --coverage /tmp/thetis-coverage

# Kernel-size and boundary checks
node --import ./lib/artifacts/source.mjs scripts/size.ts
THETIS_PACKAGES="${THETIS_PACKAGES:-../packages}" bash .github/scripts/kernel-boundary.sh

# Assemble and verify the actual release archive
node --import ./lib/artifacts/source.mjs scripts/distribution.ts /tmp/thetis-delivery
```

[CI and delivery](docs/ci-delivery.md) documents the blocking gates and signed
publication. A release reuses a successful CI artifact for the exact runtime and
packages commits. It does not rebuild untested bytes or rerun the test suite.
Production activation remains an administrator's kernel transaction.

## Architecture

The kernel owns identity, boundaries, secrets and generations. It knows no
package or model vendor. Packages declare requirements; the kernel matches
names and grants scoped capabilities. Environments, providers and gateways run
inside mandatory Linux sandboxes.

```text
kernel/       identity, boundaries, secrets and generations
lib/          shared mechanisms
contracts/    authoritative schemas, generated types and conformance tests
profiles/     assembly recipes and the offline registry seed
scripts/      development, verification and delivery tools
test/         integration tests and bounded fixtures
docs/         architecture, contracts and operating guides
```

[Packages](https://github.com/thetis-agent/packages) include the loop, terminal
and browser gateways, model adapters, file tools, registries and evaluators.
A package is an ordinary directory with a manifest and exports; no central
package registry is hard-coded into the kernel. Packages depend on libraries
and contracts, never directly on other packages.

Editable TypeScript ships with hash-verified JavaScript generated by the exact
Node version. See [execution artifacts](docs/execution-artifacts.md).
The [headless guide](docs/headless-startup.md) covers advanced source deployments,
multi-account recipes and the trusted kernel origin.

## Contribute

Read [AGENTS.md](AGENTS.md) and the design/contracts relevant to your change.
Schema, conformance tests and architecture must agree. Preserve authority,
isolation, secret custody and generation guarantees.

Run checks and tests before committing. Do not hide failing tests, loosen
acceptance budgets to get green, or rewrite main history.

ADRs are for **major architectural changes only**. Features, fixes, refactors,
defaults, workflow changes and performance budgets belong in their existing
guide and tests. Routine former records are consolidated in
[implementation notes](docs/implementation.md); their original text remains in
git history.

See [architecture records](docs/adr/README.md), [implementation status](docs/implementation-status.md)
and [remaining work](TODO.md) for the current design and evidence.
